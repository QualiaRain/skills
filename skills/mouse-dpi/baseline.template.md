# Sensitivity baseline - TEMPLATE

Copy this file to `baseline.md` (same folder) the first time this skill needs a
personal reference, then fill it in. `baseline.md` is the **only** file in this
skill that holds personal data, so it is the only one to delete before exporting
or sharing the skill; nothing else references its contents, only its name.

The one number that makes every other game a one-line calculation is the cm/360
the hand already knows. Once it is recorded, matching sensitivity in a new game
stops being a taste question and becomes arithmetic.

## Recording rules - these are the point of the file

- **Additive only.** A correction goes **below** the thing it corrects, with its
  own date, and the earlier claim stays exactly as written. Never edit or delete
  an earlier line, including a wrong one - a record that only grows can be
  audited afterwards, and drift stays visible instead of silent.
- **Date every entry** (`## YYYY-MM-DD - what changed`), and say where the number
  came from: a converge loop, their own statement, arithmetic off an earlier
  entry, or a file that was read.
- **Only record a baseline they confirmed.** It is worth having only if it is
  theirs - never infer one from whatever number a game happened to be set to.
- **Record the DPI it was settled at.** cm/360 is DPI-independent by
  construction, but the DPI is what lets a later session sanity-check the
  arithmetic against the in-game setting.
- **Two feels are allowed.** If they want a slower one for building or fishing
  and a faster one for shooters, record both as separate rows rather than
  averaging them into one wrong number.
